# 打合せ調整

複数人のMTG日程を、Google APIもサーバーもDBも使わずに決めるツール。HTMLファイル1つで動く。

## 考え方

偉い人のカレンダーは仮の予定で埋まっているので、「空いている時間に機械的に入れる」方式は成立しない。
そこで**○△×の3段階**で回答してもらい、**△を「仮の予定は入っているが動かせる／調整すれば出られる」**と明確に定義した。
カレンダー上は埋まっている枠も、動かせるなら候補として拾える。回答画面ではこの定義を目立つように出している。

データは全部URLの`#`以降に入っている。サーバーに何も保存しないし、外部にも一切送信しない。

## 準備（初回だけ）

参加者がアクセスできる場所に `index.html` を置く必要がある。
**GitHub Pages で公開する手順は [DEPLOY.md](DEPLOY.md) にまとめてある**（10分ほど。無料・恒久・HTTPS で、社外の相手にもそのまま送れる）。
社内Webサーバーや共有フォルダに置いてもよい。

置いたURLが決まったら、画面いちばん上の **「⚙ あなたの設定」** を開いて3つ入れる。打合せごとに変わらない項目なので、
一度入れればブラウザに記憶され、次回以降はここを開く必要がない（閉じた状態で内容が要約表示される）。

| 項目 | 内容 |
| --- | --- |
| あなたの名前 | 依頼文・確定連絡文の署名に使う |
| 回答を受け取るメールアドレス | 任意。入れると参加者の回答画面に「メールで返信する」ボタンが出る（後述） |
| Google Meetのリンク | 任意。入れると確定が2クリックで済む（後述） |
| このファイルの置き場所URL | 上で置いたURL。空欄ならいま開いているURLを使う |

> **自分のPC内のファイル（`file:///C:/...`）として開いた場合、発行されるURLは自分専用で他人は開けない。**
> その状態だと画面に警告が出る。動作確認だけなら問題ないが、実際に配るには置き場所が必要。

## 使い方

### 1. 候補を作って個別URLを配る

1. 件名・所要時間・議題・参加者の名前を入れる
   - **議題は参加者の回答画面に大きく表示される。** 何の打合せか分かるように書いておくと、回答してもらいやすい（改行もそのまま表示される）
   - **主催者（自分）は参加者に入れない。** 自分が出られる時間だけを候補にする
   - 場所は「＋ 場所を入れる」を開けば入れられる（任意）
   - 「メールも入れる」にチェックすると各参加者のメール欄が出る。入れておくと確定時のカレンダー登録画面に招待相手として自動で入る
2. カレンダーで候補日をクリックすると、右に「候補日 × 時刻」の時間割が出る。**マスをクリックして候補にする**
   - **日付ごとに違う時間を選べる**（8/7は10時と11時、8/8は14時だけ、など）
   - 時刻の見出しを押すとその時刻を全日まとめて、日付の見出しを押すとその日をまとめて選択／解除できる
   - 「午前を全日」「午後を全日」はよく使う時間帯を一括で入れるボタン
   - 1時間刻み。細かく刻みたいときは「30分刻み」にチェック
   - カレンダーで日付を外すと、その日の候補も一緒に消える
   - 候補は10件前後が目安。多すぎると回答率が落ちる
3. 「個別URLを発行する」を押す
4. 参加者ごとの「依頼文」ボタンでコピーして、チャットやメールで送る
   - URLは参加者ごとに違う。開くとその人の名前で回答画面になるので、名前を選ばせる手間も誤入力もない

### 2. 参加者が回答する

参加者の画面は**日程を選ぶことだけ**に絞ってある。上に「件名 → 議題 → 所要時間・場所・依頼者・自分の名前（1行）」が出て、
その下は候補日程のリストだけ。候補ごとに○△×を押して、最後に返信すれば完了。

返信の方法は、設定にメールアドレスを入れてあるかどうかで変わる。

- **入れてある場合** … 送信ボタンが2種類出る。どちらも宛先・件名・本文が入力済みなので、参加者は**送信を押すだけ**。
  件名は `【日程調整の回答】新規サービス キックオフ ／ 田中 部長` の形になるので、受信箱を見れば誰がどのMTGに答えたのか一目で分かる
  - **「メールアプリで送る」** … `mailto:` なので、そのPCの既定メールアプリが開く。Windowsでは多くの場合Outlook
  - **「Gmailで送る」** … ブラウザでGmailの作成画面が開く。**Gmailを使っている人はこちら**
    （既定がOutlookのままになっているPCは多いので、両方用意してある）
- **入れていない場合** … 回答コード（`MTG1:...`）をコピーして、チャットに貼って返信してもらう

どちらの場合も回答コードは折りたたみの中に隠れているので、参加者がコードを意識する必要はない。

- 「全部○」「全部△」「全部×」で一括入力してから個別に直せる
- 補足を書きたい人だけ「＋ 補足を書く」を開ける（初期状態では畳まれている）
- 回答内容はブラウザに保存される。同じURLを開き直せば修正して再送できる（新しいコードで上書きされる）

### 3. 集計して確定する

**トップ画面に「進行中の日程調整」の一覧がある。** 発行したMTGが回答状況（`3/5名`）付きで並ぶので、
どれがまだ揃っていないか一目で分かる。「開く」で管理画面へ、「✕」で一覧から削除できる。

一覧の下にある **「回答コードを貼る」欄が最も速い**。ここは**どのMTGのコードでも受け付ける**ので、
届いたメールやチャットをまとめてコピーして貼れば、**複数のMTG・複数人分が混在していても自動で振り分けられる**。
主催者が「これはどのMTGの回答か」を判断する必要はない。

特定のMTGを見ながら作業したい場合は、従来どおり管理画面からでもできる。

1. 「② 回答を集計する」タブを開く
2. チャットで返ってきた文章をそのまま貼り付ける（複数人分をまとめて貼れる。コード部分だけ自動で読み取る）
3. 集計表が出る。「おすすめ順」は次の優先度で並ぶ
   - 全員○ → ×なし（△混じり、△が少ない順）→ ×がある（×が少ない順）
4. 決めたい候補の「確定」を押す

読み込んだ回答はブラウザに保存されるので、日をまたいで少しずつ集めても問題ない。

## Google Meetについて

**新しいMeetリンクをその場で発行するにはGoogle Calendar APIが必須で、APIを使わない方法では実現できない。** Google側の仕様。

そのため確定パネルでは、**件名・日時・参加者・場所が全部入力済みのGoogleカレンダー作成画面を開く**ところまでを自動化している。
そこから先のクリック数は、Meetリンクを事前発行してあるかどうかで変わる。

### A. 事前発行しない場合（3クリック）

1. 「Google Meet の会議を追加」を押す（ここでMeetのリンクが発行される）
2. 「保存」を押す
3. 招待メールの確認が出たら「送信」を押す

カレンダー上に「Google Meet に参加」ボタンが出る正式な形になる。

### B. Meetリンクを事前発行しておく場合（2クリック）

[meet.google.com](https://meet.google.com/) →「新しい会議を作成」→「**後で使用する会議リンクを作成**」でリンクを発行し、
「⚙ あなたの設定」の「Google Meetのリンク」欄に入れておく。このリンクは期限なしで何度でも使い回せるし、
用途ごとに複数作ってもよい。

確定時、リンクは自動で埋め込まれる（場所欄が空ならそこへ、物理の会議室が入っているなら説明欄へ）。
あとは「保存」→「送信」の2クリック。確定連絡文にもリンクが入る。

ただしこの方法では、カレンダー上は「場所（または説明）に書かれたURL」として扱われ、
「Google Meet に参加」ボタンにはならない。参加者がURLをクリックすれば入れるので実用上の差はないが、
見た目を正式な形にしたい場合はAを使う。

## Googleの「予約スケジュール」（calendar.app.google/…）との違い

`https://calendar.app.google/xxxx` 形式のリンクは、Google Calendar の**内蔵機能**「予約スケジュール」。
短縮URLで、実体は `https://calendar.google.com/calendar/appointments/schedules/<ID>`。

一見「APIを使わずに会議を自動設定している」ように見えるが、これはGoogleが自社サービス内で自社の権限で
カレンダーに書き込んでいるだけで、外部のツールから同じことはできない（非公開の内部エンドポイントとセッション認証のため）。
仮に通信内容を解析して真似ても、規約上の問題があり、Google側の変更で即壊れる。

さらに、機能の性質がこのツールの目的と合わない。

| | Googleの予約スケジュール | このツール |
| --- | --- | --- |
| 想定用途 | 1対1（相手が1人ずつ枠を取る） | 複数人の都合合わせ |
| 判断材料 | 主催者のカレンダーの空き時間 | 各参加者の○△×の意思表示 |
| 仮予定で埋まった人 | 空きとして出ないので予約できない | △で拾える |

「複数人」「偉い人のカレンダーが仮予定で埋まっている」という前提では、予約スケジュールでは解決できない。
逆に、**1対1で相手に好きな枠を取ってほしい**場合（面談、商談など）は予約スケジュールの方が優れているので、
そちらを使えばよい。用途で使い分けるのが正解。

## 制約

| 項目 | 内容 |
| --- | --- |
| カレンダーの空き取得 | できない（APIなしのため）。候補は主催者が手で選ぶ |
| Meetリンクの発行 | 上記のとおり、事前発行なしなら3クリック・ありなら2クリック |
| 回答の自動集約 | できない。参加者が回答コードを返信し、主催者が貼り付ける |
| 配置場所 | 参加者がアクセスできる場所にHTMLを置く必要がある |

回答を自動で集めたい場合は、Cloudflare WorkersやGoogle Apps Scriptを使う構成に変える必要がある。

## 技術メモ

- 単一HTMLファイル。外部依存ゼロ、ビルド不要
- イベント情報はURLフラグメントにJSONを`deflate-raw`圧縮 + base64urlで格納（`#m=z...`）
  - 3名×8候補で約330文字、URL全体で約410文字。チャットに貼れる長さに収まる
  - `CompressionStream`が使えない環境では自動的に非圧縮（`j`プレフィックス）にフォールバック
- 回答コードは、イベント指紋（件名＋候補＋参加者から算出）を含む
  - 別のMTGのコードや、候補を変更する前の古いコードを貼ると弾かれる
  - 備考だけを直した場合は指紋が変わらないので、配ったURLと回答コードはそのまま使える
- 保存先はlocalStorageのみ（下書き、受信済み回答、参加者自身の回答）
